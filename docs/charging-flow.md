# 小程序充电流程与实现状态

本文件按用户确认的业务规则整理。小程序只有两个底部主入口：“首页”（扫码、公告、地图、消息）与“我的”（余额、订单、退款等）。设备和方案浏览可匿名完成，**发起支付前才要求登录**。

## 业务流程

1. 用户用微信扫一扫扫描设备或端口二维码；小程序将二维码原始内容发送到 `/user/scan/resolve`。
2. 后端识别设备或端口。设备码返回端口列表，端口码返回单个端口；选择设备端口时再调用 `/user/scan/port`，进入端口详情。
3. 端口详情调用 `/user/scan/offers`，只展示 PC 后台在该站点发布且启用的方案。用户不能自填金额、电量、时长或价格。
4. 方案分为金额充电和时长套餐。金额充电的支付金额由后台配置，设备实时读数按站点规则计费，达到购买金额时下发停止。套餐的价格与时长由后台配置，时长到期时下发停止。
5. 用户点击支付时，未登录则先登录；后端根据 `offer_id` 创建短期支付意图、冻结方案和计费规则，再创建微信支付单。此时不创建充电订单。
6. 已验签且核对金额的支付成功回调创建充电订单。worker 通知 gateway 启动；设备启动回执确认后进入充电中。
7. 用户主动停止、套餐到时、金额用尽，或者端口连续 1 分钟上报零功率且设备在线时，后端向 gateway 下发停止。离线或缺失端口数据不作为拔枪证据。
8. 设备结束回执提供实际电量和充电秒数。金额模式按实际计费并以已付金额封顶；套餐按使用秒数占套餐总秒数的比例收取费用。剩余款项在需要时创建退款任务，渠道确认后完成业务。

## 当前状态与待办

| 环节 | 当前状态 | 待办或验收点 |
| --- | --- | --- |
| 扫码、设备/端口详情 | 已接线，匿名访问 | 真实二维码格式和微信扫一扫进入小程序的场景参数需现场验证 |
| 后台方案 | 已有站点级金额档位、套餐价格/时长/状态的配置页和接口 | 运营数据、权限与发布流程需验收 |
| 用户选方案与登录 | 端口页只能选后台方案，支付前登录 | 小程序真机交互需验收 |
| 支付意图与回调 | 服务端冻结方案；模拟回调集成测试通过 | 真实微信商户预下单、回调、掉单补偿需联调 |
| 启动、主动停止、自动停止 | 设备命令及定时检查已接线 | B7/B8/B9/BA/BB 实机验证；金额模式缺少可靠分时计量边界读数时无法精确判定到价停机；心跳只发部分端口时，端口读数缺失与拔枪的区别需设备方确认 |
| 实际结算与退款 | 金额封顶、套餐按秒比例退款已接入现有结算和退款链路 | 真实渠道退款、异常读数人工复核及分账需验收 |
| 首页公告和地图、我的余额/订单/退款 | 已有入口和后端读取 | 首页“消息”中心尚未实现 |

接口细节见 [Go 充电生命周期接口](api/go-charge-lifecycle.md)。旧文档中的 `estimated_kwh`、`estimated_minutes`、`quote_id` 与用户自行输入金额流程仅供历史对照，不是当前小程序契约。
