# 充电方案改造实施说明

更新：2026-10-01。业务规则以 [重构方案与计算示例](charging-scheme-redesign.md) 及后续确认的服务器加时、移开后重刷规则为准。

## 已实现的业务链路

- 模板、站点方案、设备独立方案和订单快照采用同一完整 `Scheme`。应用模板时复制完整配置，设备覆盖整套替换，订单支付意图冻结套餐和整套规则。发布采用请求 UUID 和版本检查，模板修改不会重算历史订单。
- 金额入口支持最大功率、实时功率和实际电量算法；时长、电量套餐可以同时提供。功率费率采用元/小时；峰值只追溯当前自然日期的当前费率时段。电费和服务费分别累计取整，再合计。时长仅收实际完整分钟，电量套餐只购买整数度，实际 Wh 用量参与退款计算。
- 免费时长、最低电费只影响金额模式。金额与刷卡累计时长上限分别保存，默认 600 分钟。尚未确认的损耗与渠道组合拒绝启用，固定关闭损耗、1 倍渠道系数。
- 金额预算耗尽、最长时长、刷卡购买时长耗尽和用户停止记录首次计费截止点。物理结束晚于截止点时不会追加收费。不能可靠截断计量的订单进入待核对，由后台记录最终结算金额、原因和操作审计；实收始终不超过实付，不产生欠费。
- 管理端在基本信息中统一选择金额、电量、时长模式，按勾选动态生成对应模式步骤，最后配置界面展示。每种模式在同一步配置计费与套餐；金额策略归金额步骤，刷卡套餐与累计时长上限归时长步骤，满充停止归基本信息。金额计费方式切换时分别保留最大功率、实时功率、实际电量的编辑草稿；校验、预览和保存只使用当前选中的计费配置。校验错误汇总在保存按钮上方，错误字段和有关步骤标红，修正后实时更新。支持完整方案预览、站点/设备应用与继承、按所选协议显示设备能力、在线卡管理和人工结算。小程序使用已配置套餐，展示冻结方案、计费和确认状态，并支持在线卡挂失、解绑。

站点列表统一通过“管理”入口打开详情，基本信息在页内切换为表单保存，站点 ID 显示在名称后的括号中。充电站全年无休，管理端、小程序和站点接口均移除营业时间。生效方案按实际启用的金额、电量、时长模式分标签展示详细费率、套餐和策略，通用配置页展示满充停止及用户界面设置。

## DC589 在线卡

协议依据为 `docs/protocol/dc589.pdf` 的 5.8.9 版本。实现 `0xB6` 刷卡、`0xB7` 在线卡启动、`0xB8` 启动回执、`0xBD` 拒绝、`0xD0/0xD1` 状态余额查询。卡号使用非零 uint32 的十进制表示，绑定时统一卡号格式。卡余额回包按 0.1 元向下取整并限制 uint16，仅用于设备显示；实际钱包始终按整数分记账。

第一次刷卡生成支付单、完整快照、订单和启动操作，同一事务扣款。启动使用消费类型 3、平台计费模式 4、刷卡累计上限作为设备保护时长；明确启动失败退回原钱包，结果未知保持占用。补偿停止只证明设备当前关闭，不能当作“从未启动”全额退款的依据。

同一卡在原订单充电中重刷时，从原快照读取套餐；钱包扣款、支付累计金额、购买分钟数和已确认操作记录在同一事务提交。加时不发送新的 `0xB7`，不等待不存在的设备加时回执。订单已经停止、到达购买截止点、启动仍待确认、其他卡占用、余额不足或整次购买超过上限时拒绝。设备初始保护上限不会因加时改变；服务器按当前累计购买时长下发停止。停止检查与追加事务锁定同一刷卡会话，避免旧轮询结果停止刚加时的订单。

用户已确认重复刷卡须移开后重刷。网关为每个新原生刷卡报文生成 UUID，事件与待投递任务一起持久化；重试沿用原 UUID。后台冻结业务决定后再发送余额或拒绝回包，网络/数据库故障保留重试，不认定余额不足。已完成操作的查询优先返回原结果，挂失、解绑、方案变更或订单结束不改变历史结果。新事件超过接收时间 30 秒时拒绝创建新扣款，避免服务恢复后启动很早以前的刷卡；已经提交的同一事件可以继续查询。

原协议没有事件序号或移开卡事件。按已确认的设备行为，一次放卡只上报一次，移开后重刷产生新报文；每份新原生报文独立生成事件 UUID，业务投递重试沿用原 UUID。设备创建/导入时已选择匹配协议，因此直接拥有协议声明的全部执行与计量能力，不需要逐台填写核验结果。

## 数据库和启动

项目尚未发布，历史 SQL 已统一为五份 `migrations/*/0001_init.sql`，直接定义最终结构、索引和权限种子，不再新增 ALTER 或增量迁移。具体初始化和开发库重建方式见 [数据库初始化](../migrations/README.md)。新订单要求完整方案以及所选协议支持相关模式；未知协议拒绝发布，设备能力在协议注册表集中维护。

设备的运营状态独立于 TCP 在线状态，禁用设备不能新下单或刷卡，已有订单仍可停止、结算与退款。满充停止属于方案配置，参数下发与设备读回走实际协议；不再以人工核验表单阻止配置。

最终结算通过事务 outbox 发布一次 `charge_settled_stream`。事件遵循订单冻结的 `show_fee_on_end` 和 `show_fee_split`，不会在费用未知时推送虚构金额。仓库目前没有微信订阅消息投递消费者；实际微信推送需要配置模板、订阅授权和投递通道，不能把 outbox 发布当作微信投递成功。

## 验证范围

本地已验证 Go 测试与 `go vet`、管理端 TypeScript/生产构建、管理端模型测试、小程序测试，以及浏览器中的五步编辑、时段拆分、完整输入预览。后端测试覆盖重构文档的计费示例、预算截止、退款精度、幂等发布及协议原始样例；新增在线卡 MySQL 集成用例覆盖重复/并发事件、原快照加时、挂失后重放、累计付款结算和一次退款。

数据库集成用例需要已经完成迁移的独立测试数据库和 `TEST_USER_DATABASE_URL`、`TEST_ADMIN_DATABASE_URL`、`TEST_GATEWAY_DATABASE_URL`、`TEST_BILLING_DATABASE_URL` 等对应环境变量。本轮使用隔离 MySQL 8.4 和 Redis 验证 init 建表及真实事务集成测试。测试数据库只应包含可清理的测试数据。

真实 DC589 尚未验收。部署前需要实测首次启动、明确拒绝、应答丢失、持续贴卡/移开重刷、同卡加时、异卡拒绝、余额不足、累计上限、服务器到期停止、满充策略、分段计量和未使用部分退款。停止指令失败时会继续重试；数据库截止点与设备物理断电应分别核对。启动结果长期无法确认时，需运维结合设备和网关记录核对，不能凭超时自动退款或再次启动。

- 设备运营状态复用 `device_meta.status`（启用/禁用），独立于网关在线状态；新增 `device.operate` 权限及状态审计。设备列表按当前页批量读取网关厂商名称与最后心跳；扫码、下单及刷卡检查运营状态，禁用不会主动停止已有订单。
- 网关独立保存 `last_heartbeat_at`，避免把注册时间当作心跳；运营权限及心跳字段直接定义在对应 init 中。
