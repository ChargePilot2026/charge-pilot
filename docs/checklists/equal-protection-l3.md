# 等保三级测评对接 Checklist

> **引用**:`需求分析.md` § 3.4 / § 14.1 / `技术规格.md` § 9.8
> **使用**:第三方测评机构进场前自查 + 进场后逐项核对

---

## 一、安全物理环境

- [ ] 服务器放置于客户机房(物理访问控制)
- [ ] 摄像头 + 门禁记录保留 ≥ 90 天
- [ ] 防火 / 防水 / 防雷 / 温湿度控制

## 二、安全通信网络

- [ ] 网络架构图(含 VLAN / DMZ 区划)
- [ ] 边界防护设备(防火墙 / IPS)配置
- [ ] 关键链路冗余(双链路 / 双 ISP)
- [ ] 入侵检测 / 防 DDoS 策略
- [ ] HTTPS 强制:`技术规格.md` § 9.1 — Caddy TLS 1.3 + HSTS

## 三、安全区域边界

- [ ] 访问控制策略(最小权限)
- [ ] 拨号访问控制(如有)
- [ ] 默认账户修改 + 密码策略(`技术规格.md` § 12.2)
- [ ] 无线网管控(如有)

## 四、安全计算环境

### 4.1 身份鉴别

- [ ] admin 用户名 + 密码 + (二期)双因素
- [ ] 密码复杂度:长度 ≥ 8,含大小写 + 数字 + 特殊
- [ ] 密码哈希:`argon2id` 见 `技术规格.md` § 9.3
- [ ] 登录失败处理:锁定 5 min + 告警
- [ ] 登录日志 ≥ 180 天

### 4.2 访问控制

- [ ] 角色权限(`需求分析.md` § 11.2):
  - 功能级
  - 数据级(按项目 / 区域 / 站点)
  - 操作级(查看 / 审核 / 编辑 / 导出 / 删除)
  - 字段级脱敏(手机号 / 身份证 / 银行卡)
- [ ] 默认拒绝(Deny by Default)
- [ ] 特权用户权限分离(admin / auditor 分离)

### 4.3 安全审计

- [ ] admin_db.audit_log 所有写操作留痕:`技术规格.md` § 9.5
- [ ] 日志字段:`user_id` / `customer_id` / `action` / `resource` / `before` / `after` / `ip` / `user_agent` / `trace_id`
- [ ] 审计日志 ≥ 180 天保留(等保三级底线)
- [ ] 审计日志防篡改:数据库层 GRANT 隔离(只追加 / 不可 UPDATE / DELETE)
- [ ] 日志集中收集 → Loki(见 `技术规格.md` § 8.1)
- [ ] 审计告警:关键操作(删除 / 权限变更 / 大额退款)实时推送

### 4.4 入侵防范

- [ ] 最小化基础镜像:`debian:12-slim`
- [ ] 漏洞扫描:`cargo audit` 每周跑(见 `技术规格.md` § 13.6)
- [ ] 已知漏洞修复 SLA:高危 24h / 中危 7d / 低危 30d
- [ ] 网络访问控制列表(ACL)
- [ ] Webhook / API 网关限流(见 `技术规格.md` § 7.4)
- [ ] SQL 注入防护:sqlx 参数化(`技术规格.md` § 9.7)
- [ ] XSS 防护:React 自动转义 + PDF 模板白名单 escape
- [ ] CSRF:axios + JWT header(免 CSRF,见 § 9.7)
- [ ] CORS:Caddy 同源默认
- [ ] WAF(可选,客户网络层级)

### 4.5 数据完整性 / 保密性

- [ ] 数据加密传输:TLS 1.3
- [ ] 数据加密存储:`VARBINARY` + MySQL `AES_ENCRYPT`(见 `技术规格.md` § 9.3),字段:手机号 / 身份证 / 银行卡 / 邮箱
- [ ] 数据完整性:数字签名(国密 SM2/SM4 可选,客户合规要求决定)
- [ ] 备份完整性校验:定期 `mysqldump` + binlog 校验

### 4.6 数据备份恢复

- [ ] 备份策略:`技术规格.md` § 14.4 — 每日 mysqldump + 实时 binlog + 异地 OSS
- [ ] 备份保留:本机 7 天 + 异地 30 天 + 异地 OSS 长期
- [ ] 恢复演练:每半年一次完整恢复(见 `runbook/backup-restore.md`)
- [ ] RPO ≤ 1h / RTO ≤ 4h(底线)
- [ ] 配置备份:每周一次 + 异地 30 天
- [ ] 备份加密(异地 OSS 强制 AES-256)

## 五、安全管理中心

- [ ] 集中管控:运维订阅提供远程支持
- [ ] 集中审计:Loki 日志聚合 + 告警
- [ ] 集中告警:Webhook + 邮件
- [ ] 集中监控:Prometheus 指标聚合(由客户决定是否纳入客户 SIEM)

## 六、密码应用安全性(单独章节,等保 2.0 强制)

- [ ] 密码算法合规:argon2id(`技术规格.md` § 9.3)
- [ ] 密钥管理:环境变量(不读 config.yaml)
- [ ] 密钥轮转:运维订阅 + 客户合同约定周期
- [ ] 二期加"双密钥并存 24h"灰度机制(`技术规格.md` § 9.2)

## 七、个人信息保护(个保法 + 等保)

- [ ] 用户身份采集最小化:openid 隐式身份,实名/手机号绑定可选(`需求分析.md` § 5.2)
- [ ] 用户协议 / 隐私声明:首次启动强制勾选 + 系统默认模板
- [ ] 用户撤回授权:手机号解绑功能(已实现)
- [ ] 用户主动注销:软删除 + PII 抹除(`cross-reference.md` § 5.5 + `db/user.md` user 表规则)
- [ ] 第三方共享清单:Webhook 推送 / 监管对接(两类,文档明确)
- [ ] 跨境:本期**不做海外市场**,数据本地化(部署在客户所在地)
- [ ] 数据生命周期 / 销毁:`diagrams/data-lineage.md` 流程完整

## 八、测评机构交付物清单

测评机构进场后,我们交付工程师需备齐:

- [ ] 系统架构图 / 网络拓扑图
- [ ] 数据流图(DFD 0/1/2 级)
- [ ] 风险评估报告(初稿,可由测评机构复核)
- [ ] 安全管理制度文档(我们的运维订阅 SOP + 客户内部制度)
- [ ] 代码扫描报告(`cargo audit` / `cargo clippy` / `semgrep`)
- [ ] 渗透测试报告(交付前由第三方做的一次,见 `技术规格.md` § 13.6)
- [ ] 备份恢复演练报告(见 `runbook/backup-restore.md` 留痕)
- [ ] 应急响应预案(`docs/runbook/` 全部)
- [ ] 密码应用安全性自评报告
- [ ] 个人信息影响评估报告(PIA)

## 九、测评通过后

- [ ] 测评报告归档(`docs/compliance/equal-protection-l3-YYYY-MM.pdf`)
- [ ] 整改项台账 + 责任分配
- [ ] 下一次测评提醒:每年 1 次复测
- [ ] 重大变更后(如新增对外 API)重新测评
