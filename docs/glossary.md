# 术语表 / 命名规范(Glossary)

> **目的**:消除一词多义 / 多词一义。改术语时,**先改本表再改它处引用**。
> **配套**:各业务文档(`需求分析.md` / `技术规格.md` 等)的"术语表"段引用本文件。

## 一、面向技术 / 客户沟通统一术语

### 1.1 充电物理相关

| 规范用词 | 含义 | 旧用词(弃用) | 备注 |
| --- | --- | --- | --- |
| **端口(port)** | 充电插口(系统业务主语) | 枪 / 插口 / 插座 | 文案面向用户可称"插口",**技术文档一律称"端口"** |
| **设备(device)** | 单台充电桩硬件 | 桩 / 充电桩 / 主控 | 与"端口"区分(1 设备 N 端口) |
| **站点(station)** | 一组设备的物理集合 | 场站 / 充电点 / 停车场 | 见 `demand.md` § 5.9 |
| **硬件厂(vendor)** | 充电桩硬件生产厂 | 厂家 / 厂商 / 设备厂 | 客户面向用"硬件厂",代码字段统一 `vendor` |
| **适配器(adapter)** | 协议层:每家硬件厂 1 个 | 驱动 / 协议层 | 见 `技术规格.md` § 3.1.2 |

### 1.2 业务/订单相关

| 规范用词 | 含义 | 旧用词(弃用) | 备注 |
| --- | --- | --- | --- |
| **充电订单(charge_order)** | 一次完整充电会话 | 订单 / 充电单 / 工单 | 与"支付订单"严格区分 |
| **支付订单(payment_order)** | 一笔微信/余额/组合支付 | 订单 | `biz_type` 区分业务(charge / wallet_recharge) |
| **退款(refund)** | 原路返回已支付金额 | 退费 / 返还 | 仅"原路返回"才叫 refund,线下打款叫 settled |
| **分账(settlement)** | 服务费按参与方比例分配 | 分成 / 拆账 | 三种状态:`pending` / `split_done` / `settled` |
| **参与方(party)** | 分账接收方 | 分账方 / 接收方 | 字段统一 `party`,**N ≤ 8** |
| **模式 A / 模式 B** | 价费分离下的两种分账模式 | 全分账 / 仅服务费 | 见 `需求分析.md` § 9.2 |

### 1.3 客户/账户相关

| 规范用词 | 含义 | 旧用词(弃用) | 备注 |
| --- | --- | --- | --- |
| **终端用户(end user)** | 充电服务消费者(居民/骑手) | 用户 / C 端 / 充电人 | 系统内表字段用 `user`,沟通用"终端用户" |
| **客户(customer)** | 付费方(物业/运营商/政府) | 甲方 / 客户方 / 部署方 | 注意:客户不是"终端用户" |
| **管理员账号(admin user)** | PC 后台登录账号 | 后台账号 / 内部账号 | 表字段 `admin_user_role.user_id` |
| **角色(role)** | PC 后台 7 个预置角色 | 权限组 / 用户组 | 见 `需求分析.md` § 11.2 |

### 1.4 系统/部署相关

| 规范用词 | 含义 | 旧用词(弃用) | 备注 |
| --- | --- | --- | --- |
| **单客户单部署(single-tenant deploy)** | 一套系统 = 一个付费客户 | 单租户 / 独立部署 | 本系统**不做多租户 SaaS** |
| **服务(service)** | 5 个 Rust 服务(gateway/user/admin/billing/worker) | 模块 / 微服务 | 不用"子系统" |
| **Schema** | MySQL 数据库内的逻辑分组 | 库名 / 实例名 | 5 个独立 schema |
| **Stream** | Redis Stream 事件总线 | 消息队列 / Topic | 见 `技术规格.md` § 5.1(9 个) |
| **OTA** | Over The Air,远程固件升级 | 远程升级 / 推送 | 全量发布 + 双备份区 |

### 1.5 微信生态术语

| 规范用词 | 含义 | 旧用词(弃用) | 备注 |
| --- | --- | --- | --- |
| **订阅消息(subscribe message)** | 用户授权后的小程序推送 | 小程序消息 / 通知 | 需用户主动 `wx.requestSubscribeMessage` |
| **客服消息(customer service message)** | 客服主动联系用户 | 客服通知 | 见微信开发者文档 |
| **统一服务消息(uniform message)** | 一次性推送 | 旧版模板消息 | 已下线,**不要使用** |
| **客服会话(customer service session)** | 微信原生客服 | 客服 / 在线客服 | 见 `需求分析.md` § 5.8 |
| **openid** | 微信为每个用户分配的隐式身份 | 用户 ID / 微信 ID | 字段统一 `openid`,系统不要求额外认证 |

## 二、命名约定(代码 / 数据库 / API)

### 2.1 Rust 命名

- 模块名:`snake_case`
- 函数 / 变量:`snake_case`
- 类型 / 结构体 / 枚举:`PascalCase`
- 常量:`SCREAMING_SNAKE_CASE`
- 枚举变体:`PascalCase`(`ChargeState::Charging`)

### 2.2 数据库命名

- 表名:`snake_case`(单数,如 `charge_order` / `user` / `pricing_rule`)
- 字段名:`snake_case`
- 主键:`id`(无表名前缀,如 `charge_order.id` 而非 `charge_order.charge_order_id`)
- 业务唯一键:`order_no` / `device_id` / `openid` 等业务语义命名
- 索引:`pk_` / `uk_` / `idx_` 前缀
- 软删除:`deleted_at` + `deleted_by`(统一双字段,见 `cross-reference.md` § 5.5)

### 2.3 API 路径

- 资源命名:**名词复数**,如 `/api/v1/orders` / `/api/v1/devices`
- 路径参数:`{id}` 形式(Axum 0.8 语法)
- 内部接口:`/api/v1/internal/...`,经服务间共享密钥鉴权
- 公开接口:`/api/v1/public/...`(无 JWT)
- 用户接口:`/api/v1/user/...`(JWT openid)
- 管理接口:`/api/v1/admin/...`(JWT 角色)

## 三、单位 / 数字

| 类别 | 单位 | 备注 |
| --- | --- | --- |
| 金额 | **分**(BIGINT 字段后缀 `*_cents`)| 严禁浮点;展示给用户前 ÷ 100 |
| 时间戳 | ISO 8601 字符串(UTC,带 `Z`,毫秒精度) | 数据库列类型 `DATETIME(3)` |
| 功率 | 瓦(W) / DECIMAL(8,2) | 字段 `*_w` |
| 电压 | 伏(V) / DECIMAL(5,2) | 字段 `*_v` |
| 电流 | 安(A) / DECIMAL(5,2) | 字段 `*_a` |
| 温度 | 摄氏度(℃) / DECIMAL(5,2) | 字段 `*_c` |
| 电量 | 千瓦时(kWh) / DECIMAL(10,3) | 字段 `*_kwh` |
| 字节 | KB / MB / GB(2 进制或 10 进制?)→ **2 进制(KiB 等)+ GB ≈ 10 亿字节** | 文档统一,代码用 `bytes` crate |
