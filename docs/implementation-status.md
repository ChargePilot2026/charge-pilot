## 文档冲突处理

- `api/user.md` 的 P1-7 修正、`db/user.md` 和实际迁移均将 `charge_order` 放在 `user_db`；`api/admin.md` 的部分段落仍称其在 gateway，技术规格部分段落又称 billing。采用明确的 P1-7 修正：user 保存充电生命周期，billing 保存费用和分账，gateway 提供设备数据。禁止增加跨 schema SQL 来掩盖归属冲突。对外后台订单接口保持不变，内部查询由数据所有者提供。
- 现有运行环境使用 `X-Service-Token`，文档部分写 `Authorization: Bearer`。新客户端暂沿用现有内部鉴权，统一迁移与兼容测试仍列为公共基础待办。
- 数据库 SQL 与部分文档列名不一致；实现按已部署 schema 明确映射 API 字段，并随功能更新文档，不能用 `unwrap_or_default` 隐藏 SQL/反序列化错误。
