# 双模拟器本地验收

本机开发栈已初始化，预置了「双模拟器联调站」、两台 DC589 设备和包含金额、电量、时长的方案。保留本次联调订单和模拟支付记录，方便检查后台与用户端展示；所有支付都在本地模拟。

## 明早启动

在项目根目录执行（Docker Desktop 必须已经运行）：

```powershell
./scripts/dev/start.ps1
```

分别打开两个 PowerShell 终端，各执行一条命令。TUI 会占用当前终端：

```powershell
./scripts/dev/simulator.ps1 -Number 1
./scripts/dev/simulator.ps1 -Number 2
```

首次编译需要 Go 1.27。默认每台两个端口；可追加 `-Ports 10`，但后台导入时的端口数也要一致。两个模拟器拥有独立设备编号、状态文件和控制端口，不能用相同编号同时连接。启动脚本保留已有数据。

| 页面或设备 | 地址或编号 |
| --- | --- |
| 后台 | http://127.0.0.1:5173 |
| 后台账号 | `admin` / `ChangeMe!Admin2026` |
| 用户 H5 | http://127.0.0.1:5174 |
| 模拟器 1 | `5348240514082652`，控制端口 `9190` |
| 模拟器 2 | `5348240514082653`，控制端口 `9191` |
| 测试站点 | 双模拟器联调站，坐标 `116.397, 39.908` |
| 在线卡 | `100001`，归属开发账号 `tester-1` |

H5 默认账号 `tester-1`。「我的」中的本地测试账号可以切换到 `tester-2` 等账号，切换后重新登录；两个浏览器配置文件可同时使用不同用户。模拟充值入口先输入金额，再确认模拟付款。本次已经为 `tester-1` 模拟充值 10 元，并测试了刷卡扣费与退款。

新机器或重建数据库后，可运行 `node scripts/dev/prepare.mjs` 创建同样的厂商、站点、两台设备和测试方案。该脚本通过正常后台 API 创建，只补齐缺失项目，不覆盖已经编辑的配置。绑定在线卡需要先让对应用户登录，再在后台按用户 ID 绑定。

## 先测试后台

1. 登录后台，检查厂商协议为 `dc589`，厂商名称、设备运营状态和最后心跳时间正常显示。启动模拟器后等待首次心跳；断线与「禁用」是两个不同状态。
2. 在充电方案中建立或编辑方案：基本信息选择启用模式，只显示对应步骤；每个步骤一起设置费率与套餐。切换金额计费方式后切回，草稿应保留，提交只保存当前选择的算法。
3. 检查时段的开始时间、结束时间选择器、24:00 提示、功率下限、添加/删除档位；拆分时段直接执行，删除保留确认。错误汇总出现在保存按钮上方，错误字段标红。
4. 进入站点「管理」，编辑基本信息并保存。站点不再填写营业时间，ID 显示在名称后。复制并应用完整方案，再按金额/电量/时长 Tab 查看生效配置。
5. 从本站设备进入计费管理，测试设备继承站点方案、设备独立覆盖及恢复继承。对设备选定的协议直接采用其支持能力，不再逐台填写人工核验表。
6. 临时禁用一台设备，在 H5 输入其编号，检查停用提示与禁止新下单；重新启用恢复。禁用后已有订单仍应允许停止、结算和退款。
7. 在 TUI 的配置与身份页面检查参数，使用后台读写设备参数、查询端口、停止与复位等操作，对照 TUI 收发日志和物理状态。改变满充配置时让方案停止策略与设备回读一致。

预置测试方案含：1 元金额预算、1 度电（1.10 元）、1 分钟（0.01 元）、60 分钟（1 元）；刷卡购买 60 分钟，累计上限 600 分钟。金额费率按功率档位计时。它们是便于联调的价格，可在后台自行调整。

## 再测试充电用户

1. 在 H5「扫码充电」手动输入上表的设备编号，选择端口和套餐。H5 提供手动输入入口，小程序端保留扫码。
2. 用两个用户同时给两台模拟器下单，确认付款后设备真实启动，用户显示充电中；不能重复占用同一端口。
3. 先购买 1 分钟套餐，等待套餐到时自动停止；再测试金额和电量套餐。实时数据依赖设备心跳，尚未收到读数时显示暂无数据。近 30 分钟曲线按当前端口查询。
4. 主动停止充电，检查设备断电、订单结束、费用拆分和差额退款。后台周期任务约每 10 秒运行一次，退款可能稍后进入成功状态；刷新详情核对最终结果。
5. TUI 中调整功率来测试电量累计与结束；模拟拔插、满充、过流/过载、过温、烟雾、掉线/重连等情况，观察符合当前方案的停止行为。掉线不会抹去设备正在进行的充电状态。
6. 在线卡 `100001` 首次刷卡启动并从钱包购买时长；卡停留期间重复触发不应产生新事件或扣费。先「移开卡」，再刷同一卡，会由服务器购买并增加可充时长，不下发专用加时指令。订单快照应出现已确认的启动与加时记录。
7. 测试钱包充值、账单筛选、退款、手机号绑定、订单历史等页面。短时间内第三次有效钱包退款会进入人工审核并冻结钱包，后台风险处理可审批；请使用单独测试账号验证这一分支。

附近站点依赖定位；浏览器拒绝定位时使用手动经纬度，上表坐标即可看到测试站点。浏览器 H5 不需要申请微信小程序账号。

## TUI 操作

底部展示当前页面快捷键。`Tab` 切换页面，`m` 打开操作菜单，上下键选择、回车进入表单，`Esc` 返回，`q` 退出。支持端口功率、插拔、刷卡/移卡、查余额、设备参数、故障、温度、电压、烟雾、对时、断线与重连等操作；详情及协议覆盖表见 [模拟器文档](simulator-dc589.md)。配置保存与重连后的物理状态均可在 TUI 查看。

## 重建与检查

数据库尚未发布，修改五个 `0001_init.sql` 的原始建表语句即可，不增加 ALTER 或增量迁移。主动重建开发库时执行：

```powershell
./scripts/db/reset-dev.ps1 -ResetDevelopmentData
node scripts/dev/prepare.mjs
```

重建脚本先备份，再清空项目的五个开发 schema 和专用 Redis；旧联调记录会被替换。本次重建前备份位于 `.tmp/dev-db-before-reset-20261001-034902.sql`。

```powershell
./scripts/git/install-hooks.ps1
make fmt
make lint
make test
```

Makefile 直接调用 `go fmt ./...`、`go vet ./...` 和 `go test ./...`，`make check` 依次执行三项。格式化后重新暂存；提交 hook 运行 `make lint test`，CI 额外检查格式化产生的差异。Go 与 Make 均需安装；Windows 未安装 Make 时，可用 `docker compose -f compose.dev.yaml run --rm --no-deps -T central make check` 在开发容器中检查，安装提交 hook 后本机仍需 Make。完整集成测试使用隔离数据库；Linux/Git Bash 可运行 `scripts/test/integration.sh`。用户端在 `miniprogram` 执行 `npm run typecheck`、`npm test`、`npm run build:h5` 与 `npm run build:weapp`。
