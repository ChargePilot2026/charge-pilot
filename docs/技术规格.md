# 二轮车充电运营管理系统：Go 技术规格

> 业务范围以 [需求分析](需求分析.md) 为准。接口与数据字段见 `api/`、`db/`。本规格描述从头构建的 Go 后端，只有经过验收的代码才视为已实现；进度见 [Go 重建清单](migration/go-rebuild.md)。

## 1. 运行拓扑与技术选型

系统保留三个 Go 业务进程。`gateway` 处理设备连接与内部设备 API；`central` 在一个 Gin HTTP 端口按 `/api/v1/public`、`/api/v1/user`、`/api/v1/admin`、`/api/v1/billing` 分组承载用户、运营和财务逻辑；`worker` 执行定时与异步任务。Caddy 终止公网 TLS。MySQL 8.4 和 Redis 8 是基础设施。单客户单部署，五个现有 schema (`gateway_db`、`user_db`、`admin_db`、`billing_db`、`worker_db`) 暂按各自领域保留。

| 用途 | 选型 | 约束 |
| --- | --- | --- |
| 语言 | Go 1.27 | 根目录单一 `go.mod`，`cmd/` 只放入口，业务代码放 `internal/` |
| HTTP | Gin | central 单 HTTP 监听，gateway/worker 仅暴露内部 API 与健康检查 |
| 数据 | go-sql-driver/mysql + sqlc | 显式 SQL 和事务；不在 HTTP handler 拼接业务 SQL |
| 迁移 | Goose | 独立迁移步骤，业务服务启动时只验证 schema 版本 |
| 缓存和事件 | go-redis/v9 | 缓存 Redis 与 Stream Redis 独立连接；MySQL Outbox 保证事件不会因 Redis 故障丢失 |
| 鉴权 | golang-jwt/jwt/v5 | HS256 短期 token，refresh token 保存于 Redis 并轮换 |
| 计费 | shopspring/decimal | 电量和费率不使用浮点；落库和 API 金额统一整数分 |
| 微信支付 | 微信支付 APIv3 官方 Go SDK | 使用 SDK 的签名、验签、解密、支付和退款能力 |
| 汇付天下 | 官方 Go SDK，接入前核对接口覆盖 | 两渠道用统一支付端口接口，渠道选择只在后台配置 |
| MQTT | 本次暂缓 | 不启动 Broker、不监听 1883、不宣称 MQTT 能力 |

前端保持 React 管理后台和微信原生小程序。对象存储采用兼容 S3 的第三方客户端。日志、指标、追踪和导出工具在具体模块接入时选择已有库，不自行实现通用协议或格式。

## 2. 项目目录

```text
cmd/{gateway,central,worker}/
internal/{gateway,central,worker}/
internal/platform/{config,dbconn,auth,httpapi,event}/
migrations/{gateway_db,user_db,admin_db,billing_db,worker_db}/
admin-web/
miniprogram/
docker/
docs/
```

不得重建跨服务共享业务包。仅配置、鉴权、数据库连接、HTTP 包装及事件封套等通用机制放 `internal/platform`。每个领域定义自己的仓储接口和事务边界；生成的 sqlc 代码放对应领域内部。未来增加厂商协议时只新增适配器和监听配置。

## 3. HTTP 契约

- 对外 REST 路径沿用 `docs/api/` 的 `/api/v1/...` 约定；`central` 在同一个监听端口注册全部公开、用户、管理和财务路由。内部路由只通过 Docker 内网访问并校验服务令牌。
- 成功和错误均返回 `code`、`message`、`data`、`request_id`、`trace_id`；链路 ID 由入口生成或接收经校验的 `X-Request-ID`。旧文档分别使用 `request_id`/`trace_id`，新契约兼容两者。
- 时间使用 UTC ISO 8601；金额字段以 `_cents` 结尾；输入使用 Gin binding/validator 校验，拒绝未知或越界的业务值。
- 小程序用户 JWT 包含 `openid`、`user_id`、有效期；后台 JWT 包含后台用户 ID 和角色。访问控制覆盖路由、数据范围和敏感字段。
- OpenAPI 是接口发布门禁；变更 API 时同步更新 schema、前端类型和契约测试。
- 公开接口、登录、扫码启动、管理写接口按身份和 IP 限流；支付回调先验签，再进入幂等业务事务。

## 4. 数据与事件一致性

五个 schema 由独立 Goose 迁移目录管理。业务服务不在启动时自动建表。`central` 同进程承载三个逻辑模块，但数据表所有权仍按业务领域管理。跨 schema 事务仅在同一 MySQL 实例、同一连接可保证原子性时使用；外部支付、设备指令和 Redis 发布不进入数据库事务，而通过本地持久记录和事务性 Outbox 衔接。

每个资金动作都要有业务幂等键、状态前置条件和可追溯流水。支付成功回调先验签解密，再以支付单号、交易号、商户号和金额校验，在同一事务更新支付状态、钱包或充电单，并写 Outbox。发布器将 Outbox 投递到 Redis Streams，消费端以稳定事件键去重，处理成功后才确认。未知支付或退款结果必须向支付渠道查询，不能靠超时推定成功或失败。

扫码、选端口只读。创建订单与支付请求时占用端口逻辑锁；**只有已验证成功的支付回调**才能触发设备启动。设备启动 ACK 与端口持久占用在业务事务中确认；失败或取消先关停设备并走退款补偿。端口排他以数据库唯一约束为最终防线，Redis 锁只做短期并发协调。设备结束上报先持久化，再产生结算事件；价费分离分别计算和入账。

## 5. 计费、退款和分账

- 计费支持时长、电量、功率档位、峰平谷时段和会员模板。按时段累计电费与服务费，再分别按客户确认的舍入规则结算；不得将总价反拆为两条费用。
- 扣减顺序固定为会员卡、优惠券、余额、微信。赠送余额、充值优惠、会员卡和优惠券须有独立有效期、核销与审计记录。
- 启动失败、超过 10 小时、60 秒内取消等按需求自动退款；提前拔出或余额不足按实结算后退差额。计量异常进入人工审核。退款记录和原支付单的累计已退金额必须保持一致。
- 分账人数 2–8，比例用基点存储且合计 10000。模式 A 分配电费与服务费；模式 B 只分配服务费，电费单独记账。分钱尾差按确定性规则分配，账单、对账、提现及导出均能复算到原始流水。

## 6. 设备协议与安全

`gateway` 提供每协议独立 TCP 监听配置。第一份厂商协议的内部名称为 `dc589`，默认监听 `:9100`；其它协议可绑定 `:9101` 等新端口。每个适配器负责厂商帧编解码及命令映射，向设备业务层输出统一的注册、心跳、遥测、启动结果、停止结果、结束订单和故障事件。只有已建档、已启用且协议匹配的设备可以完成登录。

`dc589` 以用户提供的 5.8.9 协议附件为准：`EE | LEN | CMD | SESSION_ID(6) | DATA | XOR`，多字节数据为小端。上线必须覆盖 A0/A1 登录、A4/A5 心跳、B7/B8 启动、B9/BA 停止、BB/BC 结算、C0/C1 故障、配置与 A2 OTA 指令；文档示例报文作为测试向量。设备消息持久化成功后再回 ACK。安全遥测和故障阈值按需求触发高危断电与通知。协议附件中的 SIM 示例含非十进制 BCD 半字节，适配器对可选标识保留原始十六进制值。

`dc589` OTA 的固件下载由设备连接厂商服务器完成。平台只能下发升级指令、跟踪心跳与版本并告警；双备份自动回滚是否由设备保证，需要厂商资料和实机验证。未证实前，不能把平台命令等同于回滚能力。MQTT 此次不开发或暴露。

## 7. 业务模块清单

`central` 包含用户身份与可选手机号、协议/隐私同意、站点与找桩、扫码和订单、钱包与充值、会员、优惠券四种发放机制、支付渠道、退款和风控、评价投诉、客服、发票、设备/站点/定价管理、白标和公告、角色权限、告警、Webhook、分账、账单、对账、提现、OTA 管理和监管报送。`worker` 承担 Outbox 发布、Stream 消费重试和 DLQ、过期与清理、聚合、对账、通知、告警推送、OTA 超时扫描及备份检查。详细验收点以需求章节和 `docs/api/` 契约为准。

## 8. 部署与切换门禁

Docker Compose 先起 MySQL、Redis 和独立迁移任务，再起三个 Go 服务及 Caddy。`admin-web` 构建产物由 Caddy 提供。生产只开放 80/443 与已配置的设备 TCP 端口，内部 Gin 端口不映射公网。密钥通过环境变量或只读文件注入；不得提交真实商户密钥。数据库仅有测试数据，可在迁移验证后重建。

单次切换前必须完成：全部需求和 API 功能实现、Go 单元/集成/端到端测试、设备协议模拟与实机验证、支付渠道测试交易与回调、退款和分账对账、五 schema 迁移、故障演练、容量测试及安全检查。当前缺测试商户资料与 `dc589` 实机/OTA 证明，所以支付渠道和设备回滚不能宣称验收通过，也不得执行生产切换。
